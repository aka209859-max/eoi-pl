## ❌ 発生している問題

### 1. CSV エクスポート時の文字化け
PostgreSQLから馬名をCSVエクスポートすると、以下のように文字化けする：

**期待する結果**:
```csv
ketto_toroku_bango,bamei
2022110071,ジーティービバーイ
2021100845,エスヴィーマト
```

**実際の結果**:
```csv
ketto_toroku_bango,bamei
2022110071,?W?[?e?B?[?????o?C?@?@?@?@?@?@?@?@?@
2021100845,?G?X?V?[???}?g?@?@?@?@?@?@?@?@?@?@?@
```

### 2. データベース内部の状態確認結果

**実行したSQL**:
```sql
SELECT 
    ketto_toroku_bango,
    bamei AS 現在の表示,
    encode(bamei::bytea, 'hex') AS バイト列
FROM nvd_se 
WHERE kaisai_nen = '2026'
LIMIT 3;
```

**結果**:
```
 ketto_toroku_bango |              現在の表示              |                    バイト列
--------------------+--------------------------------------+--------------------------------------------------
 2019102067         | ???C???X?g???C?J?[?@?@?@?@?@?@?@?@?@ | 3f3f3f433f3f3f583f673f3f3f433f4a3f5b3f403f403f40...
 2022102633         | ?A???W?j?[?X?@?@?@?@?@?@?@?@?@?@?@?@ | 3f413f3f3f573f6a3f5b3f583f403f403f403f403f403f40...
 2020105199         | ?E?C???g?????F?[???@?@?@?@?@?@?@?@?@ | 3f453f433f3f3f673f3f3f3f3f463f5b3f3f3f403f403f40...
```

**バイト列の解析**:
- `3f` = ASCII の `?` (クエスチョンマーク)
- `40` = ASCII の `@` (アットマーク)
- `43` = ASCII の `C`
- `57` = ASCII の `W`

→ **データベース内に既に `?`、`@`、アルファベットという文字として格納されている**

## 🔧 試した解決策（全て失敗）

### 試行1: convert_from() 関数による変換
```sql
SELECT 
    ketto_toroku_bango,
    convert_from(bamei::bytea, 'SJIS') AS 変換後
FROM nvd_se 
WHERE kaisai_nen = '2026'
LIMIT 3;
```

**結果**: `ERROR: bytea型に対する不正な入力構文`

**理由**: データベース内に既にShift_JISのバイナリデータではなく、ASCII文字（`?`、`@` など）が格納されているため、Shift_JISからの変換が不可能。

### 試行2: UTF-8エンコーディング指定でのエクスポート
```cmd
chcp 65001
psql.exe -U postgres -d pckeiba -c "\copy (SELECT ketto_toroku_bango, bamei FROM nvd_se WHERE kaisai_nen = '2026') TO 'output.csv' WITH CSV HEADER ENCODING 'UTF8'"
```

**結果**: 文字化け継続（`?W?[?e?B?[` など）

### 試行3: 環境変数設定
```cmd
setx PGCLIENTENCODING UTF8
```

**結果**: 文字化け継続

## 🤔 推定される原因

### 仮説: データインポート時の破損

PC-KEIBAソフトが `.nvd` ファイル（Shift_JISエンコーディング）からPostgreSQLへデータをインポートする際に、以下のいずれかが発生した可能性：

1. **エンコーディング変換失敗**: Shift_JIS → UTF-8 変換時にエラーが発生し、変換不可能な文字が `?` に置換された
2. **クライアントエンコーディング不一致**: PostgreSQL接続時のクライアントエンコーディング設定が不適切で、バイト列が誤って解釈された
3. **SQL_ASCIIモード**: PostgreSQLがバイト列をそのまま格納したが、その後の取得時に文字化けが発生

### 重要な事実
- **サーバーエンコーディング**: `UTF8` (確認済み)
- **クライアントエンコーディング**: 初期状態 `SJIS`、SET後 `UTF8` (どちらでも文字化け)
- **バイト列**: 既にASCII文字（`3f`, `40` など）として格納済み
- **元のShift_JISバイナリデータ**: 既に失われている
